## Aufgabe 1

Welche Formen von Tests kennen Sie aus der Informatik?
Arbeiten Sie zu zweit und erläutern Sie mind. drei Beispiele, die Sie aus der Praxis kennen.
Wie werden die Tests durchgeführt?

Folgende Testarten kennen wir:

- Unit Test
- Integrationstest
- End to End Test
- Stresstest
- Volumentest
- Penetrationstest
- Failover Test

### Unit Test
Bei einem Unit Test testet man eine einzelne Methode oder Klasse, ohne den Rest vom System. Die Tests schreibt der Entwickler selber, z.B. mit JUnit in Java oder Jest in JavaScript. Man gibt der Methode bestimmte Werte rein und prüft, ob das richtige Resultat rauskommt. Sie laufen lokal in der IDE und automatisch in der Pipeline bei jedem Push. Wenn einer fehlschlägt, wird nicht gemerged.

### Integrationstest
Hier schaut man, ob mehrere Teile zusammen funktionieren, z.B. ob das Backend die Daten richtig in die Datenbank schreibt oder ob die Anbindung an eine externe API klappt. Dafür nimmt man oft eine Testdatenbank in einem Docker Container und ruft die REST Endpoints auf, automatisiert oder von Hand mit Postman.

### End to End Test
Beim E2E Test wird die ganze Applikation so getestet, wie sie ein Benutzer braucht, also vom Frontend bis zur Datenbank. Mit Playwright schreibt man Skripte, die den Browser steuern: einloggen, Produkt in den Warenkorb, bestellen. Danach wird geprüft, ob die Bestellung auch angezeigt wird. Die Tests sind langsam und laufen deshalb meistens nur vor einem Release oder in der Nacht.

### Stresstest und Volumentest
Beim Stresstest schaut man, wie sich das System unter sehr hoher Last verhält und ab wann es zusammenbricht, z.B. bei tausenden Anfragen gleichzeitig. Beim Volumentest geht es eher um grosse Datenmengen, z.B. eine Tabelle mit mehreren Millionen Einträgen. Für beides gibt es Tools wie JMeter oder k6, die viele Benutzer simulieren und die Antwortzeiten messen.

### Penetrationstest
Ein Pentest versucht Sicherheitslücken zu finden, so wie es ein Angreifer machen würde. Zum Beispiel ob man ohne Login auf Daten zugreifen kann oder ob SQL Injection möglich ist. Das machen meistens externe Firmen oder Spezialisten mit Tools wie Burp Suite oder OWASP ZAP, aber vieles ist Handarbeit.

### Failover Test
Hier testet man, ob das System weiterläuft, wenn eine Komponente ausfällt, z.B. ein Server oder die Datenbank. Man schaltet absichtlich einen Teil ab und schaut, ob ein anderer Server übernimmt und ob dabei Daten verloren gehen.

## Aufgabe 3

Eine Software gliedert sich in der Regel in eine Reihe von Teilsystemen, die wiederum aus einer Vielzahl elementarer
Komponenten besteht. Wir haben im V-Modell gesehen, dass es verschiedene Teststufen gibt. Wir wollen in diesem
Zusammenhang nun ein Beispiel der untersten Stufe anschauen.

**Beispiel Test in der Klasse Preisberechnung**

In der Auto-Verkauf Software werden Preise mit Rabatten versehen.
Wir haben folgende Elemente und Regeln:
Es besteht ein Grundpreis (*baseprice*), abzüglich Händlerrabatt (*discount*).
Dazu kommen Sondermodellaufschlag (*specialprice*) und der Preis für weitere Zusatzaustattungen (*extraprice*).
Wenn drei oder mehr Zusatzausstattungen (*extras*) ausgewählt werden, dann erfolgt ein Rabatt von 10% auf diesen
Ausstattungen. Wenn es fünf oder mehr Zusatzausstattungen sind, dann ist der Rabatt bei 15%.
Der Händlerrabatt bezieht sich auf den Grundpreis. Der Zubehörrabatt gilt nur für den Preis der Zubehörteile.
Ein Code würde somit so aussehen:

`

        double calculatePrice(double baseprice, double specialprice, double extraprice, int extras, double discount) {
            double addon_discount;
            double result;
            
            if (extras >= 3) 
                addon_discount = 10;
            else if (extras >= 5)
                addon_discount = 15;
            else 
                addon_discount = 0;
            
            if (discount > addon_discount)
                addon_discount = discount;
            
            result = baseprice/100.0 * (100-discount) + specialprice
                    + extraprice/100.0 * (100-addon_discount);
            
            return result;
	    }

`

Setzen Sie diesen Code in Ihrer Entwicklerumgebung um. Erstellen Sie nun einen entsprechenden *Testtreiber*, um diese Preisberechnung zu testen. Ein Testtreiber ist ein Programm, das die jeweiligen Schnittstellenaufrufe (Methoden-Aufruf) ausführt und anschliessend das Resultat zurückerhält. Skizzenhaft würde das so aussehen:

`
    
    boolean test_calculate_price(){

        double price;
        boolean test_ok = true;
    
        < your code>

    }
`
Achtung: Wir schreiben hier keine Unit-Tests. Unit-Tests werden wir später im Modul anwenden.
Stellen Sie Ihre Tests ins Repository und zeigen Sie Ihre Lösung der Lehrperson.
