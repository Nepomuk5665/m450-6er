## Übung 1

Wir haben folgende Beschreibung einer Verkaufssoftware:

*Über die Verkaufssoftware kann das Autohaus seinen Verkäufern Rabattregeln vorgeben: Bei einem Kaufpreis von weniger
als 15’000 CHF soll kein Rabatt gewährt werden. Bei einem Preis bis zu 20’000 CHF sind 5% Rabatt angemessen. Liegt der
Kaufpreis unter 25’000 CHF sind 7% Rabatt möglich, darüber sind 8,5 % Rabatt zu gewähren.*

Leiten Sie aus dieser Beschreibung Testfälle ab. Wir wollen beide Varianten von Testfällen untersuchen.

* Eine Tabelle mit abstrakten Testfällen. Hier verwenden Sie logische Operatoren wie > , < , etc.
* Eine Tabelle mit konkreten Testfällen. Hier verwenden Sie ganz konkrete Eingabe-Werte, um die Testfälle zu erstellen.

### Abstrakte Testfälle

| ID | Kaufpreis x (CHF) | Erwarteter Rabatt |
|---|---|---|
| A1 | x < 15'000 | 0% |
| A2 | 15'000 <= x <= 20'000 | 5% |
| A3 | 20'000 < x < 25'000 | 7% |
| A4 | x >= 25'000 | 8.5% |
| A5 | x <= 0 | Fehlermeldung, ungültiger Preis |

Bei genau 25'000 ist die Beschreibung nicht ganz klar, weil "unter 25'000" 7% gibt und "darüber" 8.5%. Wir haben angenommen, dass 25'000 schon zu den 8.5% gehört. A5 steht nicht in der Beschreibung, sollte aber trotzdem abgefangen werden.

### Methoden für White-Box Tests

| Klasse | Methode | Was man testen kann |
|---|---|---|
| Account | `withdraw(amount)` | Beide Pfade: Betrag grösser als Kontostand gibt false, sonst wird abgezogen und true zurückgegeben. Grenzwert: Betrag genau gleich wie Kontostand. |
| Account | `deposit(amount)` | Betrag wird zum Kontostand addiert. Negativer Betrag (wird im Moment nicht geprüft). |
| Account | Konstruktor | ID wird bei jedem neuen Konto um 1 hochgezählt. |
| Bank | `getAccount(nr)` | Konto gefunden, Konto nicht gefunden (null). |
| Bank | `createAccount(...)`, `deleteAccount(a)` | Konto ist danach in der Liste bzw. nicht mehr, `getNumberOfAccounts()` stimmt. |
| Bank | `printAccountDetails(a)` | Konto existiert, Konto wurde schon gelöscht. |
| Counter | `convertCurrency(...)` | Jede if-Bedingung (USD->CHF, USD->EUR, CHF->USD) und der Fall ohne Umrechnung. Die Methode ist aber private. |
| Counter | `transferAmount(from, to)` | Kontostand zu tief, gleiche Währung, andere Währung. Liest aber direkt vom Scanner. |
| ExchangeRateOkhttp | `getExchangeRate(from, to)` | Gültige Antwort, Fehler bei der Abfrage gibt 0.0 zurück. Dafür müsste man den HTTP Aufruf mocken. |

### Verbesserungen und Best Practices

- Logik und Ein-/Ausgabe trennen. Die Klasse `Counter` liest vom Scanner, gibt Text aus und rechnet gleichzeitig. Darum kann man z.B. `transferAmount` fast nicht testen. Besser wäre eine eigene Klasse für die Logik und `Counter` nur für die Eingaben.
- Beträge prüfen. Negative Beträge werden überall angenommen (B9 bis B11). Bei B11 kann man so Geld von einem fremden Konto holen.
- Leere Eingaben abfangen. `input.substring(0,1)` stürzt bei einer leeren Eingabe ab (B15), gleich in `getConfirmation()`.
- Wechselkurse. Die Kurse in `convertCurrency` sind fix im Code, falsch herum (USD->CHF mit 1.11) und es fehlen Kombinationen wie EUR->CHF. Die App hat schon eine Wechselkurs API, die könnte man auch für Überweisungen brauchen.
- API Key nicht im Code. Der Key für die Wechselkurs API steht direkt in `ExchangeRateOkhttp` und ist damit für alle sichtbar. Besser als Umgebungsvariable oder in einer Config Datei, die nicht ins Git kommt.
- BigDecimal statt double für Geld. Mit double gibt es Rundungsfehler.
- Exceptions richtig verwenden. Statt `catch (Exception e)` und dann `instanceof` die Exceptions einzeln abfangen. Eine `NumberFormatException` wird im Hauptmenü einfach verschluckt (B17). Ausserdem hat `AccountExeption` einen Tippfehler.
- Fehlermeldungen korrigieren. Im Hauptmenü steht "u" statt "w" (B16).
- Kein static Zähler für die Konto ID. Wegen `static int counter` hängen die IDs davon ab, wie viele Konten vorher erstellt wurden. In Tests ist das mühsam.
- Aufräumen. Das Enum `Currency` in eine eigene Datei, auskommentierten Code löschen, das TODO in `getAccount` erledigen (z.B. mit Stream und Optional).
- Unit Tests schreiben. Der Ordner `src/test` ist leer.
